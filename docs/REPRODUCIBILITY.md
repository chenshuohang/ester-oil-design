# 复现范围、环境和方法变化

## 可以复现什么

1. 从本包的输入表按固定种子和记录下来的划分运行 13 套 QSAR 训练。
2. 加载随包原有 QSAR 权重进行性质预测。
3. 从明确允许的结构 CSV 重建自编码器输入、训练 AE、编码训练结构、训练条件 DiT。
4. 用训练所得生成模型和性质模型进行多目标搜索并导出候选。

“可运行且可追踪”不等于跨硬件、依赖版本逐位相同，也不等于保证获得原论文完全相同的指标。每次训练保存输入哈希、实际配置、环境和划分。CPU 单线程下做了同一种子重复训练检查；GPU 浮点归约可能产生差异。

## 安装与硬件

- 已验证 Python 3.11、CPU 单线程；直接依赖在 `environments/requirements-*.txt` 固定版本，实际安装环境的完整版本快照见 `environments/tested-environment.json`。
- QSAR 的 PyTorch 可以用 CPU 或兼容 CUDA 的官方 wheel；选择 `--device cuda` 才使用 CUDA。
- JAX 配置保留 0.4.28 / Flax 0.8.3。生成 CPU 测试设置 `JAX_PLATFORMS=cpu`。
- CUDA 12 的 JAX 运行时可另装 `jax-cuda12-plugin==0.4.28` 和 `jax-cuda12-pjrt==0.4.28`；GPU 驱动与 CUDA 环境不由本包安装，本次未验证 GPU 运行。
- 新仓默认单进程，不再假定存在 8 张 GPU。原训练入口保留分布式参数，但多节点运行没有在本次测试中验证。

正式 AE 和 DiT 网络远大于 smoke 小模型。完整语料准备会产生较多分子图文件，正式训练应按实际硬件容量设置 batch size。长时间训练不在本次整理中自动执行。

## 明确的方法变化

- 清除服务器绝对路径，输入和输出由命令行绑定。
- 保留原有 QSAR 训练超参数和划分实现；补记实际过滤后的索引及输入哈希。
- 生成训练从允许的 PubChem + BRICS500 结构重新构建。按 canonical isomeric SMILES 去重，固定种子 90/10 划分；不复用历史混合训练列表。
- 编码阶段仅使用 AE 训练子集；本版编码全部训练结构，不实施历史笔记本的“重构命中后再筛选”。
- 条件和无条件 DiT 分支都读取这份允许训练结构的潜变量；无条件分支丢弃条件标签。此配比与历史额外预训练语料混合不同。
- 条件标签仍为原实现的双键数、不饱和度、分子量、环数、logP 和可旋转键数；保留固定归一化范围以便模型接口一致。
- 关闭 AE 的专用 Flash Attention 路径以便 CPU 和普通 JAX 使用；不是逐位重现旧 GPU kernel。
- 修复条件数据加载器在批次端点相同时返回空批次的问题；训练结束始终保存 `params_final.pkl`，步数使用 int32。
- 搜索固定使用本仓带约束的 NSGA-II。历史运行可能根据依赖环境选择 UNSGA3 或 NSGA-II，不能据本版实现倒推历史分支。
- 解码器对未分配词表 ID 给出无效候选并使用现有回退流程，避免随机初始化模型产生未知 ID 时崩溃。

## 历史权重与排除数据

13 个基线权重来自原有 `qsar/tasks/`，逐个核对训练数据路径和样本数，并检查与被排除目录的文件哈希不重复。历史动力黏度 directed 文件的内部 model_name 较笼统，预测器以保存的架构字段判断模型类型，不仅按文件名猜测。

未附带历史生成模型、混合索引或潜变量，因为无法从本地历史记录严格拆分其中的来源。不存在“只删文件夹但继续让脚本依赖该文件夹”的默认复现步骤。
